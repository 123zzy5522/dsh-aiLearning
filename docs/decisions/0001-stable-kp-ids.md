# 0001. 知识点 id 用「章 + 节」，不用抽取顺序

- 状态：已采纳
- 日期：2026-10-21
- 相关：[#8](https://github.com/123zzy5522/dsh-aiLearning/pull/8)、`host/store.js`、`host/migrate.js`

## 背景

最初的 id 是 `KP-0203`（第 2 章第 3 个抽出来的知识点），由 `mergeChapter` 按批次顺序递增生成。

问题在第一次重抽时暴露：只重跑第 2 章的一批，第 2 章后面的所有知识点、以及第 3 章之后的分章编号都会变。`events.jsonl` 里记的是旧 id，于是：

- 已答过的题对不上任何知识点（掌握度表里多出“已删除”条目）；
- 覆盖台账把学过的又算成“从没测过”；
- **没有任何报错**，只是数据悄悄错位。

这本书当时 412 页、191 个知识点，建库还在反复重跑（33/39 批），重抽是常态。

## 选项

| 选项 | 好处 | 代价 |
|---|---|---|
| 保持位置 id | 零改动，id 短 | 每次重抽都掉进度；越晚改越贵 |
| 内容哈希（正文 hash） | 内容不变就稳定 | 改一个错别字就换 id；抽取器微调也会漂 |
| 章 + 节号 `KP-02-2.1.3` | 重抽同一节不变；人眼可读、能反查页码 | 依赖目录识别质量；无节号时要兜底 |
| 数据库自增 + 映射表 | 最稳 | 引入一个必须维护的映射；Markdown 不再是唯一事实来源 |

## 决定

用**章 + 节号**：`KP-<章>-<节>`；该条目没有数字节号时，退化为 `KP-<章>-h<标题哈希>`。

## 理由

- 节号来自书本身，重抽同一节必然得到同一个 id，和抽取顺序无关。
- id 自带定位信息：看到 `KP-02-2.1.3` 就知道是哪一章哪一节，排查时不用查表。
- 迁移成本此刻最低：`events.jsonl` 还是空的（0 次答题），191 条 md 可以机械改写。

## 后果

- **好**：重抽一章不再丢进度；id 可读；迁移脚本幂等，可反复跑。
- **不好**：
  - 如果目录识别把某节标错，id 会跟着错——错误从“顺序”转移到了“节号”。
  - 没有节号的条目只能用标题哈希，标题一改就换 id（已接受：这类条目通常是“本章小结”）。
  - 两节归一化后同名时靠 `-2` 后缀去重，这种 id 不稳定（极少见）。
- **重新考虑的信号**：如果引入跨书的知识点（同一概念在两本书里），节号就不够了，需要“书 + 节”或本体 id。
